# Frontend / Backend 병렬 개발 및 통합 워크플로

## 통합 전제
- Architect가 API 계약(권장: OpenAPI 또는 동등한 문서)을 확정합니다.
- 요청/응답 필드, 타입, nullable, 오류 형식, 인증, 페이지네이션을 명시합니다.
- 공통 타입/스키마 파일의 작성자를 지정합니다.

## 병렬 개발
- Frontend는 승인된 API 계약을 기준으로 Mock API/fixture를 이용해 개발할 수 있습니다.
- Backend는 같은 계약으로 실제 API와 DB 연동을 구현합니다.
- 각 역할은 서로의 소스 디렉터리를 수정하지 않습니다.
- 계약 변경은 Architect가 관리하고 양쪽 담당자에게 통지합니다.

## 개발자 통합 확인
Frontend와 Backend는 다음을 확인합니다.
- 요청 URL/메서드/헤더/본문 일치
- 응답 스키마 및 오류 형식 일치
- 인증·권한 동작
- 데이터 저장 후 조회 및 화면 반영
- 중복 제출, 타임아웃, 네트워크 오류
- 날짜/시간대, 숫자/통화, 페이지네이션 등 도메인 특수 케이스

## QA 통합 검증
QA는 개발자 확인과 별도로 실제 환경에서 주요 흐름을 재실행합니다. API·로그·DB·브라우저 증거를 조합해 결과를 판단합니다.

## 계약 불일치 처리
임의로 한쪽 구현을 맞추지 않습니다. 불일치 내용을 기록하고 Architect와 Controller가 명세 변경 여부를 결정합니다.
