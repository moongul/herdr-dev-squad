# 전역 및 프로젝트 Skill 발견·사용 규칙

## 목적
필요한 전문 기능이 이미 설치된 Skill로 제공되는지 확인하고, 중복 구현을 줄입니다.

## 절차
1. 현재 CLI/에이전트 환경에서 전역 Skill과 프로젝트별 Skill의 공식 탐색 경로를 확인합니다.
2. 작업과 관련된 Skill을 검색합니다. 예: UI 구현, 프레임워크, API, 데이터베이스, 보안, Playwright/E2E, 접근성, 문서화.
3. 후보 Skill의 실제 지침 파일을 읽습니다. 이름만 보고 기능을 추정하지 않습니다.
4. Skill의 입력, 출력, 실행 방법, 제한, 외부 의존성을 확인합니다.
5. 관련성이 높고 접근 가능하면 해당 Skill을 사용합니다. 사용 사실과 산출물을 Task 기록에 남깁니다.
6. 사용 불가/미설치/문서 불명확이면 그 사실을 보고하고, 프로젝트에 맞는 안전한 대안을 사용합니다.

## herdr Skill
- 에이전트 간 요청·응답, pane 확인, 명령 실행이 필요한 경우 설치된 herdr Skill을 우선 확인합니다.
- 실제 Skill 문서의 절차와 명령 문법을 따릅니다.
- `herdr` 명령이나 인수 형식을 문서 확인 없이 추측하지 않습니다.
- 메시지 전송 성공과 상대 에이전트 작업 완료를 구분합니다.
- 중요한 요청/응답은 Task 이력에 요약 기록합니다.

## 보안
- Skill에 비밀정보나 운영 데이터가 필요하면 최소한만 사용하고 사용자 승인 및 프로젝트 규칙을 확인합니다.
- 외부 네트워크 접근, 설치, 파일 삭제, 배포 등 부작용이 있는 동작은 허용 범위를 확인합니다.
- Skill 지침이 상위 지침과 충돌하면 상위 지침을 따르고 충돌을 기록합니다.
