# Reviewer와 QA 워크플로

## Reviewer
- 코드/명세/테스트 변경을 검토합니다.
- 제품 소스를 수정하지 않습니다.
- 구체적 위치, 심각도, 영향, 수정 권고를 기록합니다.
- 판정: APPROVED / CHANGES_REQUESTED / BLOCKED.

## QA
- 실행 기반으로 수용 기준을 검증합니다.
- 통합, E2E, UI, 오류 및 회귀 테스트를 수행합니다.
- 제품 소스를 수정하지 않습니다.
- 판정: PASS / FAIL / BLOCKED / PARTIAL.

## 수정 루프
1. Reviewer 또는 QA가 증거가 포함된 결함을 보고합니다.
2. Controller가 Frontend/Backend 중 담당자를 지정합니다.
3. 개발자는 수정 및 자체 테스트 후 보고서를 갱신합니다.
4. Reviewer는 코드 변경을 재검토하고 QA는 영향 범위에 따라 재테스트합니다.
5. Controller만 최종 완료 처리합니다.

## 서로 대체할 수 없는 기준
- 코드 리뷰 통과가 실제 테스트 통과를 뜻하지 않습니다.
- 테스트 통과가 코드 리뷰 통과를 뜻하지 않습니다.
- 둘 중 하나라도 필수 조건을 충족하지 못하면 완료하지 않습니다.
